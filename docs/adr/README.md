# Architecture Decision Records

Short records of the important decisions in ThinkXecAI: the problem, the options considered, what was chosen and why, and the trade-offs.

| ADR | Decision | Date |
|---|---|---|
| [001](adr001_ci_pipeline.md) | CI with GitHub Actions runs backend tests against a real PostgreSQL + pgvector database | 2026-10-02 |
| [002](adr002_api_response_shape.md) | API responses return the resource directly inside a single `{ code, message, data }` envelope | 2026-10-02 |
| [003](adr003_hnsw_vector_index.md) | HNSW instead of ivfflat for vector search, so small knowledge bases return correct results | 2026-10-02 |
| [004](adr004_typed_message_metadata.md) | Project-owned types for tool-call metadata stored on chat messages | 2026-10-02 |
| [005](adr005_database_owned_timestamps.md) | The database sets all timestamps; chat messages use `clock_timestamp()` to keep their order | 2026-10-03 |
| [006](adr006_uuid_type_handler.md) | A UUID type handler instead of string ids and SQL casts | 2026-10-03 |
| [007](adr007_java21_spring_boot_3_5_16.md) | Java 21 and Spring Boot 3.5.16 | 2026-10-04 |
| [008](adr008_mapper_tests_real_database.md) | Data-layer tests run on the real database and roll back | 2026-10-04 |
| [009](adr009_jsonb_defaults.md) | Missing agent settings in JSON columns fall back to the database defaults | 2026-10-04 |
| [010](adr010_recent_message_window.md) | Agent memory loads the latest N messages in chronological order, not the first N | 2026-10-04 |
| [011](adr011_gemini_model_provider.md) | Gemini (`gemini-3.8-flash`, native integration, API key) replaces OpenAI; Spring AI raised to 1.1.8 | 2026-10-06 |
| [012](adr012_gmail_oauth_email_tool.md) | The email tool sends through the Gmail API with OAuth 2.0 (send-only scope) and a fail-closed recipient allowlist | 2026-10-06 |
| [013](adr013_request_validation_and_error_codes.md) | Bean Validation on request bodies; client errors return 400 / 404 / 409 naming the field, everything else a generic 500 | 2026-10-07 |
| [014](adr014_knowledge_base_deletion_cleans_agent_references.md) | Deleting a knowledge base removes its id from every agent's allowed list in the same transaction | 2026-10-07 |
| [015](adr015_agent_chat_options_merge_and_ranges.md) | Agent chat options are merged field by field on update and range-checked (temperature 0–2, topP 0–1, messageLength 1–100) | 2026-10-07 |
| [016](adr016_chat_session_agent_fixed.md) | A chat session's agent is fixed at creation; updates change only the title | 2026-10-08 |
| [017](adr017_user_messages_start_agent_runs.md) | Only user messages start an agent run; the agent comes from the session; bad requests are rejected (400 / 404 / 409) before saving | 2026-10-08 |
| [018](adr018_session_activity_ordering.md) | Adding a message refreshes its session's updated_at, so sessions are listed by latest activity | 2026-10-08 |
| [019](adr019_document_metadata_server_managed.md) | Document metadata (it holds the stored file path) is written only by the server, never accepted in requests | 2026-10-08 |
| [020](adr020_api_description_matches_json.md) | The generated API description marks response fields required, and nullable only where annotated; chat options split into request and response classes | 2026-10-09 |
| [021](adr021_api_contract_check.md) | Frontend API types are generated from the backend's description and committed; a CI job fails when they drift or no longer typecheck | 2026-10-09 |
| [022](adr022_ollama_embeddings_spring_ai.md) | Embeddings come from local Ollama `bge-m3` through Spring AI's `EmbeddingModel` (`/api/embed`, batched, unit-length vectors); the old endpoint's unnormalized vectors skewed L2 ranking | 2026-10-11 |
| [023](adr023_markdown_sections_keep_source.md) | Markdown section content is the original source between headings, so tables, code, lists, and links reach the agent as written; titles stay plain text for embedding | 2026-10-11 |
| [024](adr024_strict_order_filtered_vector_search.md) | Knowledge-base search sets strict-order iterative HNSW scanning for its own transaction, so a small knowledge base is not crowded out by others (0 → 3 of 3) | 2026-10-11 |
| [025](adr025_atomic_markdown_upload.md) | Markdown upload validates and embeds first, then writes the document, file, and chunks in one short transaction; any failure leaves nothing (no more silent zero-chunk documents) | 2026-10-12 |
| [026](adr026_file_cleanup_after_commit.md) | Deleting a document or knowledge base removes its files only after the commit; a rollback keeps them, and a failed file deletion is logged, not returned | 2026-10-12 |
| [027](adr027_optional_gmail_credentials_synchronous_send.md) | Gmail settings are optional and named at the first send; the email tool sends synchronously with one 10 s deadline shared by the self-made OAuth token refresh and the Gmail call; strict single-recipient parsing against the fail-closed allowlist | 2026-10-14 |
| [028](adr028_read_only_database_tool.md) | The SQL tool runs each query in its own read-only transaction with a 5 s database timeout plus a driver timeout (a query can switch the first off) and a 200-row cap; the superuser connection's remaining reach (file reads, ending connections, app tables) is accepted until a dedicated account in v2 | 2026-10-14 |
| [029](adr029_knowledge_tool_scoped_to_allowed_kbs.md) | The knowledge tool searches only the running agent's allowed knowledge bases, passed in Spring AI's tool context where the model cannot change them; other or malformed ids get an explanatory answer | 2026-10-13 |
| [030](adr030_sql_tool_single_statement_own_connection.md) | The SQL tool runs exactly one statement (counted by the driver's parser), on its own connection that is always rolled back and closed, with values cut at 1,000 and answers at 20,000 characters; review found `SELECT 1; COMMIT; DROP ...` and pooled-session leaks (amends 028) | 2026-10-16 |
| [031](adr031_chat_message_api_user_only.md) | The chat-message API takes only user messages (`{ sessionId, content }`) and has no PATCH; assistant, tool, and system messages and their tool-call metadata are written only by the agent runtime (amends 017) | 2026-10-17 |
| [032](adr032_request_size_limits.md) | Request fields have size limits (names 200, descriptions 2,000, system prompt and message 20,000 characters; tool and knowledge-base lists 50 entries; upload names 200), and the knowledge-base lookup binds one `uuid[]` parameter instead of one per id | 2026-10-17 |
| [033](adr033_loopback_only_and_host_check.md) | The backend listens on `127.0.0.1` only and refuses any `Host` but `localhost` / `127.0.0.1` with 403 (DNS rebinding); PostgreSQL is published on `127.0.0.1` only; CORS no longer allows credentials | 2026-10-17 |
| [034](adr034_database_sessions_in_utc.md) | Every database session runs in UTC (pool init SQL; the SQL tool sets it in its transaction), so `TIMESTAMP` columns hold UTC and daylight saving time cannot reorder messages; a zone in the JDBC URL is overridden by the driver; tests run in Australia/Sydney | 2026-10-17 |
| [035](adr035_section_content_keeps_first_line_indentation.md) | Markdown section content drops only leading blank lines and trailing whitespace, so an indented code block that opens a section keeps its indentation (amends 023) | 2026-10-17 |
| [036](adr036_upload_and_embedding_limits.md) | Uploads take at most 500 sections and refuse NUL characters and too-deep nesting before embedding; Ollama's own client has a 5 s connect and 60 s read timeout; NUL in JSON text and malformed multipart bodies are 400, not 500; the parser's worst-case CPU is accepted | 2026-10-17 |
| [037](adr037_row_locks_for_concurrent_writes.md) | Concurrent writes take row locks: `FOR UPDATE` before agent and knowledge-base merges, `FOR SHARE` on rows a request checks, `FOR NO KEY UPDATE` on a session before a message; knowledge bases are locked before agents to avoid deadlocks; a row deleted meanwhile gives 404 / 400, not 500 | 2026-10-17 |
| [038](adr038_gemini_response_one_assistant_message.md) | A Gemini response becomes one assistant message: non-thought text joined, every function call kept with its id, the calls' thought signatures in order (works around spring-ai #5466 and split text answers) | 2026-10-18 |
| [039](adr039_chat_model_timeouts_and_retry.md) | Both chat models' HTTP clients are built by the application: 10 s connect and 120 s read timeout (for Gemini, the whole call); a failing call is tried at most 3 times, 2 s × 3 apart, through Spring AI for DeepSeek and the SDK for Gemini | 2026-10-18 |
| [040](adr040_chat_client_registry.md) | `ChatClientRegistry` holds exactly the clients named in `ChatModelNames` (checked at startup; unknown names throw `IllegalArgumentException`); both clients default to `internalToolExecutionEnabled = false` and set no sampling options | 2026-10-18 |
| [041](adr041_runtime_instructions_one_system_message.md) | The model gets one system message: the agent's prompt, the starting design's decision guidance in English, and the agent's knowledge bases (`id: name — description`); tool names outside the run's tools are answered with an error text instead of ending the run | 2026-10-19 |
| [042](adr042_one_run_at_a_time_per_session.md) | Runs of one chat session execute one at a time (a per-session `CompletableFuture` chain on `asyncEventExecutor`, removed when idle), different sessions in parallel; the listener only hands off; a rejected run's notice is saved outside the finished transaction before the next run starts; in-process only | 2026-10-19 |
| [043](adr043_failed_runs_leave_a_notice.md) | A run that cannot finish saves an assistant notice with a generic reason (model failed, agent gone, model unavailable, too busy, 20 steps, unexpected); a deleted session saves nothing | 2026-10-19 |
| [044](adr044_generated_message_publisher.md) | Generated messages go to `GeneratedMessagePublisher` (Phase 11: logging; Phase 12: SSE); publisher failures are caught and never affect a run | 2026-10-19 |
| [045](adr045_terminate_needs_an_answer.md) | `terminate` ends a run only in an assistant message that has text; called without text it is answered with "Not ended: …" and the loop goes on; its description and the runtime guidance tell the model the user sees only its text (seen with Gemini) (amended 2026-10-21: the call after a refused `terminate` offers no tools) | 2026-10-20 |
| [046](adr046_run_answers_its_own_message_last.md) | A run's memory ends with the user message it answers: `ChatEvent` carries its id, memory is the latest `messageLength` up to it plus everything after, the trigger moved last and newer questions left out (Gemini refuses requests that end with the model's turn) | 2026-10-21 |
| [047](adr047_sse_unknown_session_real_status.md) | The SSE stream opens only for an existing session: unknown session → real HTTP 404, an id that is not a UUID → real HTTP 400, a failed lookup → real HTTP 500, each with the envelope as JSON (a controller-scoped handler with a preset content type), so a browser `EventSource` stops instead of reconnecting; `GET` only | 2026-10-21 |
| [048](adr048_sse_replaced_event.md) | Still one stream per session; connecting again sends the old stream a `replaced` event before completing it, so the old tab stops instead of reconnecting and taking the stream back; callbacks remove only their own emitter | 2026-10-21 |
| [049](adr049_sse_close_after_session_delete.md) | Deleting a session completes its stream after the delete commits (a rollback leaves it open), so the reconnect gets 404; connect checks the session, registers, and checks again, closing only its own stream on a failed second check (PR #18 review) | 2026-10-21 |
| [050](adr050_qwen_chat_model.md) | `qwen3.8-flash` added as a third chat model through Spring AI's OpenAI client (module without its starter, own `thinkxecai.chat.qwen.*` settings so `SPRING_AI_OPENAI_*` cannot redirect it) on Model Studio's OpenAI-compatible endpoint (international site), same timeouts and retry as DeepSeek; the Gemini key becomes optional (not configured → "model is not available" notice) and Gemini is no longer tested against the real API (its free tier took 56–109 s per answer) | 2026-10-24 |
| [051](adr051_frontend_versions_and_cooldown.md) | Frontend versions raised (`react-router` 8, React 19.2.9, Vite 8, ESLint 10, Ant Design X 2.9) and pinned exactly, each only after 14 days on npm; unused `react-contexify` / `emoji-picker-element` removed; remaining `katex` / `mermaid` advisories accepted because neither is bundled, with a lint rule refusing their imports; amended 2026-11-03: unused `@ant-design/x` removed, which drops `mermaid` | 2026-11-01 |
| [052](adr052_frontend_unit_tests_vitest.md) | Frontend unit tests on Vitest with jsdom and React Testing Library, configured in `vite.config.ts`, run in CI; `fetch` and `EventSource` faked per test; first tests pin the HTTP client's envelope and error handling | 2026-11-01 |
| [053](adr053_self_hosted_fonts.md) | Instrument Sans and JetBrains Mono bundled from Fontsource packages instead of loaded from Google Fonts: no third-party request, works offline, versions pinned | 2026-11-02 |
| [054](adr054_agent_profile_route.md) | Clicking an agent opens its profile at `/agent/:agentId` (setup, Start chat, Edit, Delete) instead of a new chat; Start chat goes to `/chat?agent=<id>`; agents and knowledge bases become shared contexts | 2026-11-02 |
| [055](adr055_english_ui_and_working_indicator.md) | The UI is English; the chat shows the agent working, inferred from its newest message (user, tool call, or tool result), off at an answer or notice, at the results of an answer that called `terminate` (amended 2026-11-03), or 7 minutes after that message's own time; display only | 2026-11-02 |
| [056](adr056_english_jvm_locale.md) | `main` sets the JVM's default locale to English before Spring starts, so the PostgreSQL driver's "Position" / "Hint" labels in tool results are not translated into the machine's language (seen as `位置：37`) | 2026-11-03 |
| [057](adr057_service_not_answering_is_503.md) | An outbound call that gets no answer (`ResourceAccessException`: read timeout, refused connection) is a 503 with a generic "try again" / "check that it is running" message, mapped once in the error handler so later models and services need no code; the URL goes only to the log (amends 013; seen with a cold Ollama) | 2026-11-03 |
| [058](adr058_quieter_look_ink_actions.md) | A quieter look: stone ground, ink primary buttons, Think indigo and Execute orange used only for steps, mono only for model ids and tool names, text tags with a small mark instead of pills, labelled rail without the robot icon and with a white focus ring (replaces the V1 palette) | 2026-11-04 Amended 2026-11-06: one centred column; selected options in stone. |
| [059](adr059_run_shown_as_a_trace.md) | A run is a trace, not a chat reply: the user's message on a band with `>`, no card, V4 step rail kept, each tool call with a one-line result summary that opens in place, a skeleton row with a timer while working, steps folded into "N steps in T s" when the answer arrives; the new-chat page stays (amends 055) | 2026-11-04 |
| [060](adr060_stopping_a_run.md) | `POST /chat-sessions/{id}/stop` stops the running run and the runs queued behind it, checked before each Think and Execute; each stopped run saves a "Stopped." notice; retry sends the question again; Send becomes Stop in the UI (adds to the feature scope; amends 042, 043) | 2026-11-04 |
| [061](adr061_motion_with_css_transitions.md) | Motion answers the user: 150 ms ease-out CSS transitions only (no library), Ant Design's motion tokens matched, one form chosen per motion (rail grows for a new step, height-only expand, icon shape change on Send/Stop, folding row and rising Undo bar, colour and a slight press), off under reduced motion | 2026-11-04 Amended 2026-11-06: the content fades in rising 8 px on a page change. |
| [062](adr062_whole_app_in_docker_on_request.md) | A Compose profile `app` runs the backend and frontend in Docker on request; a plain `docker compose up` and CI still start only PostgreSQL; ports stay on the host's loopback (ADR 033) and Ollama stays on the host. | 2026-11-06 |
| [064](adr064_tool_failure_kinds.md) | Every stored tool result records `failure`: `null`, `UNKNOWN_TOOL`, `INVALID_ARGUMENTS`, `REFUSED`, or `TOOL_ERROR`, set by the backend where the outcome is known, with the model's text unchanged; for counting failures later and keeping the UI off backend wording; older messages not filled in (amends 041) | 2026-11-08 |
